# Contributing

Thank you for considering a contribution to [PROJECT NAME]. This guide explains how to propose changes clearly.

## Before you start

1. Read the README and any project-specific policies.
2. Search existing issues and pull requests to avoid duplicate work.
3. For large changes, open an issue first to discuss the approach.

## Local setup

1. Fork the repository.
2. Clone your fork.
3. Install the project's documented dependencies.
4. Create a branch for your change.

```bash
git checkout -b type/short-description
```

Suggested branch prefixes: `feat/`, `fix/`, `docs/`, `test/`, `refactor/`.

## Make your change

- Keep changes focused and easy to review.
- Follow the style already used in the project.
- Add tests when behavior changes.
- Update documentation when instructions or behavior change.
- Never commit passwords, API keys, tokens, private keys, or personal data.

## Commit messages

Use a short, descriptive message, for example:

```text
docs: clarify installation steps
fix: handle empty input
feat: add task export
```

## Open a pull request

1. Push your branch to your fork.
2. Open a pull request against the correct base branch.
3. Explain the problem, your solution, and how you tested it.
4. Link any related issue.
5. Respond constructively to review feedback.

## Reporting issues

Use the repository's issue templates when available. Include reproducible steps and relevant environment details. Remove secrets and personal information from logs.

## Review and conduct

Maintainers may ask for changes, decline contributions that do not fit the project's scope, or close inactive discussions. Be respectful and explain disagreements with technical reasoning.

## Questions

Open a discussion or issue using the project's documented channels.
